# Formato: <arquivo em _shared/> <hash-do-arquivo-LF-16hex> <data> [except=fn1,fn2,...] <motivo>
#
# Responde a pergunta "um arquivo de _shared/ que a function importa tem commit mais
# novo que o deploy dela?". Sem reconhecimento, cada function afetada aparece como
# "STALE via _shared/<arquivo>". Com reconhecimento valido, elas viram UMA linha de
# resumo ("RECONHECIDO: N function(s) pendentes so por _shared/<arquivo>") e nao contam
# como problema -- cada uma sai do resumo no proprio deploy natural.

# - Vale pra UM arquivo, num conteudo EXATO: se o arquivo mudar de novo (1 byte), o hash
#   diverge e todas as functions voltam a aparecer como STALE via _shared. Reconhecer de
#   novo exige olhar a nova mudanca.
# - Mudanca em _shared/ pode ser gap REAL (ex.: buildPlanPayload.ts sem deploy do
#   get-plan-payload = Caso 9). So reconheca quando a mudanca e comprovadamente inofensiva
#   pras functions que nao forem deployadas agora, e escreva o porque no motivo.
# - except= lista as functions que PRECISAM do deploy: elas continuam aparecendo como STALE
#   de proposito, pra ninguem esquecer. Sem espaco depois das virgulas.
# - Quando nenhuma function depender mais do reconhecimento (todas deployadas depois do
#   arquivo), a saida do check mostra OBSOLETO -- remova a linha.
