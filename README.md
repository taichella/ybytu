# ybytu

## Scripts

- `bash scripts/detect-silent-revert.sh <ref-base> <ref-pr>` — antes de mergear uma PR, avisa se ela remove uma linha que `ref-base` também mudou depois que a PR divergiu (ex: `bash scripts/detect-silent-revert.sh origin/main origin/nome-da-branch`).
- `bash scripts/deploy-functions.sh <nome-da-function>` — **use no lugar de** `npx supabase functions deploy`, nunca antes dele. Recusa o deploy se a function (ou `_shared/`) tiver mudança não commitada, ou se o commit atual ainda não chegou no remoto — só então roda o deploy de verdade. Sem argumento, aplica a mesma checagem a `supabase/functions/` inteiro (deploy de todas). Existe porque `supabase functions deploy` manda o que está em disco sem nunca olhar pro git: dois geradores de plano e o webhook do WhatsApp ficaram dias rodando em produção sem existir no repositório até uma varredura manual achar (2026-09-06). Bypass de emergência (documentar o motivo, não usar em silêncio): `ALLOW_DIRTY_DEPLOY=1 bash scripts/deploy-functions.sh <nome>`.
- `bash scripts/check-stale-deploys.sh` — auditoria da direção oposta ao script acima: compara o commit mais recente de cada edge function (e dos arquivos de `_shared/` que ela de fato importa) contra o timestamp real de deploy no Supabase, e avisa quando existe commit mais novo que o deploy — código correto no repo, produção rodando a versão velha, sem aviso nenhum de sistema (Caso 9 do padrão, achado 2026-09-14: o commit do token `'coco'` no mapa de badge foi criado só pra evitar essa janela, e o deploy correspondente nunca rodou). Não bloqueia nada, só lista. **Rodar antes de qualquer teste com aluno real, e depois de qualquer sessão que tenha mexido em edge function.** **`STALE` indica suspeita, não confirmação — confirme por conteúdo antes de redeployar** (`npx supabase functions download <nome> --use-api --project-ref <ref>` e `diff --strip-trailing-cr` contra o arquivo local): o checkout local usa CRLF e o que sai do Supabase vem em LF, então um `diff` comum marca o arquivo inteiro como diferente mesmo sem nenhuma mudança de conteúdo — quase redeployamos 6 functions sem necessidade por causa disso em 2026-09-14 (nenhuma das 8 sinalizadas naquele dia tinha divergência real, timestamp só documentava tardiamente código que já estava no ar).
  - **Duas perguntas separadas (desde 2026-09-27):** `STALE (propria)` = a pasta da function tem commit mais novo que o deploy; `STALE via _shared/<arquivo>` = um arquivo de `_shared/` que ela importa tem commit mais novo que o deploy. Cada uma tem a sua lista de exceção, e as duas exigem hash de conteúdo (mudou 1 byte, o aviso volta):
    - `scripts/stale-allowlist.txt` — falso positivo de CRLF **confirmado por diff** na pasta da function. Hash só da pasta: `node scripts/check-stale-deploys.mjs --print-hash <function>`.
    - `scripts/stale-shared-ack.txt` — mudança em `_shared/` **conscientemente não deployada** (ex.: o CORS de 2026-09-27, +2 origens sem uso até a virada). Uma linha por arquivo: `<arquivo> <hash> <data> [except=fn1,fn2] <motivo>`. As functions reconhecidas viram uma linha de resumo `RECONHECIDO`; as do `except=` continuam aparecendo como STALE de propósito, porque precisam do deploy. Hash: `node scripts/check-stale-deploys.mjs --print-shared-hash <arquivo>`. **Só reconheça mudança comprovadamente inofensiva:** mudança em `_shared/` também pode ser gap real (`buildPlanPayload.ts` sem deploy do `get-plan-payload` é o Caso 9).
    - Entrada que não suprime/reconhece mais nada aparece como `OBSOLETO` na saída — remova. O motivo da separação: o commit do CORS acendeu 28 STALE de uma vez, e um deploy esquecido de verdade ficaria invisível no meio deles.
- `cd apps/ybytu-dashboard && npx vite --config vite.preview.config.js` — renderiza uma tela do dashboard com dados de fixture, sem precisar de login de staff (bloqueado localmente por CORS); abra `/preview/index.html?screen=exercises` (adicione telas novas em `preview/main.jsx`).
